# 航空餐食按需履约

约定航班餐食选择、供应批次、装载和替代权益的处理方式。

## 领域资料

`contracts/` 存放可直接用于校验的 JSON Schema 契约，`fixtures/` 提供不含真实个人信息的示例。`src/` 下的模块负责读取、校验这些资料并执行履约链规则，后续业务服务可以沿用其中的领域标识与版本约定。

当前资料记录了以下业务事实：

- 航司提供弃餐换里程或优惠券
- 特殊旅客仍享有免费特殊餐保障
- 延误场景可向旅客发放机场电子餐券

## 契约

- `contracts/context.schema.json`：基础领域资料格式
- `contracts/flight.schema.json`：航班及其四个履约阶段的时点
- `contracts/supplier.schema.json`：供应商、可服务机场与供应批次（含成分）
- `contracts/passenger.schema.json`：脱敏旅客，只含匿名标识、座位、特殊需求、过敏原与权益列表，禁止姓名、证件号等身份字段

`src/schema.js` 实现了契约所用的 JSON Schema 子集，测试直接以契约校验示例资料。

## 履约链规则

- **阶段冻结**（`src/stages.js`）：值机截止 → 配餐装车 → 登机口确定 → 起飞，按顺序冻结；阶段冻结后该阶段数据禁止改写。
- **权益守恒**（`src/ledger.js`）：每项权益只发放一次、了结一次；弃餐兑换按约定价值记入里程/优惠券账户，退款必须等于已付金额；儿童、低糖等基础保障权益只能履约、改领餐券或随航班合并转移；合并时权益转出转入总数守恒。
- **唯一兑现**（`src/redemption.js`）：同一权益在机上装载、跨机场补配、供应商替换、离线补录任一渠道兑现后，其他渠道一律拒绝重复兑现。
- **唯一装载版本**（`src/manifest.js`）：同一航班同一时刻只有一个有效装载版本，新版本发出即作废旧版本，乘务组只能读取有效版本；阶段冻结后禁止再出该阶段新版本。
- **最小可见**（`src/manifest.js`）：乘务组视图只含座位、餐型与过敏提示；供应商视图只做餐型数量与过敏约束聚合，不含任何旅客标识；替代餐含旅客过敏原时禁止替换。

## 本地校验

运行 `npm test` 可确认示例资料符合契约，且上述冻结、守恒、唯一兑现与最小可见规则生效。示例中的编号均为虚构值，不包含账号、凭据或真实主体信息。
